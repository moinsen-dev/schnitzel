# F033 Implementation Summary: Dart Freezed Optional/Nullable Fields

## Overview
Feature F033 has been successfully implemented to handle optional/nullable fields in Dart Freezed models generated by the Schnitzel Framework.

## Implementation Details

### 1. New Files Created

#### `/src/schnitzel/generators/dart/models.py`
A complete Dart Freezed model generator with the following capabilities:
- Generates `@freezed` annotated classes
- Handles required fields with `required` keyword
- Handles optional fields with nullable type syntax (`Type?`)
- Supports all Dart type mappings from `DART_TYPE_MAP`
- Generates proper JSON serialization support
- Creates appropriate part directives for `models.freezed.dart` and `models.g.dart`

#### `/src/schnitzel/generators/dart/__init__.py`
Module initialization file that exports `DartModelGenerator`.

#### `/tests/integration/test_dart_optional_fields_f033.py`
Comprehensive test suite with 8 test cases covering:
1. `test_required_field_has_required_keyword` - Verifies required fields use `required` keyword
2. `test_optional_field_has_nullable_type` - Verifies optional fields use nullable syntax
3. `test_mixed_required_and_optional_fields` - Tests models with both field types
4. `test_all_optional_model` - Tests models where all fields are optional
5. `test_various_dart_types_with_optional` - Tests optional flag with various Dart types
6. `test_list_types_with_optional` - Tests optional flag with list types
7. `test_freezed_structure` - Verifies proper Freezed structure and annotations
8. `test_default_optional_is_false` - Verifies default behavior (optional=False)

### 2. Key Features

#### Required Fields (optional=False)
```dart
@freezed
class User with _$User {
  const factory User({
    required String id,
    required String name,
  }) = _User;
}
```

#### Optional Fields (optional=True)
```dart
@freezed
class User with _$User {
  const factory User({
    String? bio,
    int? age,
  }) = _User;
}
```

#### Mixed Required and Optional Fields
```dart
@freezed
class User with _$User {
  const factory User({
    required String id,
    required String name,
    String? bio,
    int? age,
  }) = _User;
}
```

## Usage Example

```python
from schnitzel.schema.models import SchnitzelSchema, Model, FieldDefinition
from schnitzel.generators.dart.models import DartModelGenerator

# Define schema
schema = SchnitzelSchema(
    models={
        "User": Model(
            name="User",
            fields={
                "id": FieldDefinition(type="string", optional=False),
                "name": FieldDefinition(type="string", optional=False),
                "bio": FieldDefinition(type="string", optional=True),
                "age": FieldDefinition(type="int", optional=True),
            }
        )
    }
)

# Generate Dart code
generator = DartModelGenerator()
dart_code = generator.generate(schema)

# Or write to file
output_path = generator.generate_to_file(schema, "lib/models")
```

## Implementation Notes

### Design Decisions
1. **Part Directives**: Uses `models.freezed.dart` and `models.g.dart` for multi-model files
2. **Default Behavior**: When `optional` is not specified, it defaults to `False` (required)
3. **JSON Serialization**: Includes `fromJson` factory method and proper part directives
4. **Type Safety**: Properly distinguishes between required and optional fields using Dart's type system

### Schema Integration
The implementation uses the existing `FieldDefinition.optional` attribute from `/src/schnitzel/schema/models.py`:
```python
class FieldDefinition(BaseModel):
    type: str
    optional: bool = False  # Used by F033
    # ... other fields
```

### Freezed Structure
Generated models follow Dart Freezed best practices:
- `@freezed` annotation for immutable data classes
- Const factory constructor
- Mixin with generated `_$ModelName`
- JSON serialization via `json_serializable`
- Proper part directives
